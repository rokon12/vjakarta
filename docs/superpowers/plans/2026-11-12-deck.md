# Deck Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The 45-minute JakartaOne deck, built on vfun's engine, telling the story the demo app measured: faster first, then the big sale breaks it, then the limits are written down, then deadlines.

**Architecture:** Copy vfun's `slides-src/` into `vjakarta/slides-src/`. The engine (`core/`) and the tools are reused as they are. Typographic slides are rewritten in `tools/gen_slides.py`, notes in `tools/notes.py`. Two vfun scenes are reused unchanged (`carriers`, `race`), two are reused with new data (`overload`, `timeout`), two are new (`p99`, `service`). The build writes one self-contained HTML file.

**Tech Stack:** Node (build and checks), headless Chrome in `/Applications` (screenshots), Python 3 (generators), the vfun engine (`core/core.js`).

**Spec:** `docs/superpowers/specs/2026-11-11-jakartaone-talk-design.md` (the reuse map and running order). Every number comes from `docs/numbers.md`. Before writing any scene, read `slides-src/specs/_contract.md` (copied from vfun): it is the engine's API and the design system.

## Global Constraints

- Do not edit `core/` (`core.js`, `base.css`, `theme.css`, `chrome.html`). The contract says so, and it keeps the look identical to vfun.
- Every number on a slide is in `slides-src/specs/_numbers.md`. That file is `docs/numbers.md` plus the vfun numbers this deck reuses (the 1,000-request race, the structured-concurrency timeline), copied verbatim.
- Every line of Java on a slide is copied from the vjakarta tag it belongs to (`git show <tag>:<path>`), trimmed but never retyped or improved. Elided lines are shown as `…`.
- Projector and livestream rules from the contract: no meaningful text below 28 px, strokes that carry meaning at least 3 px, colours only with their contract meanings (red late or leaked, green done in time, yellow lock, grey turned away).
- Scene JavaScript: no libraries, no network, no `console.log`, only `ctx` for timing, small named functions, no comments that restate the code.
- Speaker notes in plain English, the way vfun's notes ended up: what is on screen, how to read it, what to say.
- The deck builds to `vjakarta/slides.html` (git-ignored, the copy to present from) and is copied to `vjakarta/index.html` (the one a Pages site would serve later). Nothing is pushed.
- Build every scene inline in this session. No multi-agent fan-out.

## Review Focus

- Livestream video compresses the screen share: hatching, thin lines and small grey text turn to mush. Every scene slide's key frame is also looked at scaled down to 1280 × 720 (Task 8).
- A number on screen that is not in `_numbers.md`, or differs from it. `tools/numbers_check.py` lists every number in the built deck's text that the sheet does not contain (Task 2 test, Task 8 run).
- A code slide that drifts from the tagged code. `tools/code_check.py` checks every code line on a slide against its tag (Task 3 test and run).
- The speaker jumps to any step, goes backwards or reloads mid-talk, and a new scene shows a half state. `selftest` steps every slide both ways; each new scene's still frames are screenshotted with motion off (Tasks 4–7).
- The talk runs long. The notes' minute marks must be in order and the last slide (`links`) must start by minute 43, leaving two minutes for questions inside the slot (Task 8).
